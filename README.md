## เริ่มรันในเครื่อง

ใช้ **Node.js 24 ขึ้นไป** และ npm ต้องแตก ZIP ก่อน แล้วเปิด Terminal ในโฟลเดอร์ที่มี `package.json` ของ Campus Time Capsule (ไม่ใช่โปรเจกต์ Pokédex เดิม)

```bash
npm install
npm run dev
```

เปิด **Local URL ที่ Terminal แสดง** โดยปกติคือ http://localhost:3000 หากพอร์ตถูกใช้อยู่จะเป็นเลขอื่น ต้องเปิด Terminal ค้างไว้ ไม่ใช่ดับเบิลคลิกไฟล์ HTML

บน Mac สามารถเปิดโฟลเดอร์ใน Terminal แล้วใช้ `bash START-MAC.command` บน Windows ใช้ `START-WINDOWS.bat` ได้เช่นกัน

**ค่าเริ่มต้นใช้โหมด local:** สมัครสมาชิก สร้าง เปิด ลบ และบันทึกความรู้สึกได้จริง ข้อมูลอยู่ใน SQLite ฝั่ง server ที่ `.data/capsule.sqlite` ไม่ใช่ localStorage รีเฟรชหรือปิด–เปิด server แล้วข้อมูลยังอยู่ และข้อความที่ยังล็อกจะไม่ถูกส่งไปเบราว์เซอร์

โหมด local มีไว้รันส่งงาน/เดโมบนเครื่อง ไม่ใช่ Supabase จำลอง ทั้งสองโหมดใช้รหัสผ่านแคปซูลแบบ Argon2id และกติกาเปิดเดียวกัน หากต้องการใช้ Supabase ตาม proposal ให้ทำตามหัวข้อถัดไป

### หากรันไม่ได้

- `npm: command not found`: ติดตั้ง Node.js 24 แล้วเปิด Terminal ใหม่
- ไม่พบ `package.json`: อยู่ผิดโฟลเดอร์ ให้เปิดโฟลเดอร์ที่แตก ZIP นี้
- เห็นหน้า Pokédex: กำลังเปิดคนละโปรเจกต์ ให้ดู Local URL ของ Campus Time Capsule ที่รันอยู่
- พอร์ตไม่ว่าง: ใช้ URL ล่าสุดที่ Terminal แสดง หรือ `npm run dev -- --port 5300`
- เบราว์เซอร์ไม่เชื่อมต่อ: ตรวจว่า Terminal ยังรันอยู่และไม่มีข้อความ error
- หากใช้งานในเครื่องด้วย HTTP ให้ใช้ `npm run dev` เพราะ production session cookie ใช้ Secure และควรรันผ่าน HTTPS

## เชื่อม Supabase ตาม proposal

1. สร้าง Supabase project ของกลุ่ม
2. เปิด SQL Editor แล้วรันเนื้อหาทั้งไฟล์ `supabase/schema.sql` เพื่อสร้างตาราง สิทธิ์ และฟังก์ชันบันทึกข้อมูล
3. คัดลอก `.env.example` เป็น `.env.local` แล้วกรอกค่าของ project:

```dotenv
DATA_BACKEND=supabase
SUPABASE_URL=https://YOUR-PROJECT.supabase.co
SUPABASE_ANON_KEY=YOUR-ANON-KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR-SERVICE-ROLE-KEY
```

4. ใน Supabase Auth ตั้ง Site URL เป็น URL ของเว็บ เช่น http://localhost:3000 สำหรับทดสอบ
5. หากเปิด Confirm email ผู้สมัครต้องยืนยันอีเมลก่อนเข้าสู่ระบบ เว็บจะแจ้งหลังสมัคร ไม่ต้องปิดการยืนยันอีเมลเพื่อให้ใช้งานได้
6. หยุด server แล้วรัน `npm run dev` ใหม่ สมัครบัญชีใหม่ในโหมด Supabase

**อย่าใส่ service-role key ในตัวแปรที่ขึ้นต้นด้วย `NEXT_PUBLIC_` หรือส่งไฟล์ `.env.local` ให้ผู้อื่น** โค้ดเข้าถึง Supabase จาก server เท่านั้น

ข้อมูลโหมด local และ Supabase เป็นคนละชุด ไม่มีการย้ายข้อมูลให้อัตโนมัติ เมื่อใช้ Supabase ต้องเชื่อมต่ออินเทอร์เน็ต Session จะมีอายุตาม access token ของ Supabase เมื่อหมดอายุให้เข้าสู่ระบบใหม่ เวอร์ชันนี้ไม่ทำ automatic refresh

ไฟล์โค้ดเชื่อม Supabase และ SQL เตรียมให้แล้ว แต่ต้องกรอกข้อมูล project ของผู้ใช้ก่อน จึงยังไม่ได้ทดสอบกับ Supabase project จริงในการจัดทำไฟล์นี้

## เดโมให้เห็นการทำงานครบ

1. สมัครสมาชิกแล้วเข้าสู่ระบบ
2. สร้างแคปซูล ใส่ข้อความอย่างน้อย 10 ตัวอักษร
3. เลือก **อีก 2 นาที** แล้วตั้งรหัสผ่านแคปซูลอย่างน้อย 8 ตัวอักษร (แนะนำให้ต่างจากบัญชี)
4. ติ๊กยอมรับเงื่อนไขแล้วปิดผนึก เว็บแสดงนับถอยหลัง ก่อนถึงเวลาไม่มีเนื้อหาข้อความส่งมายัง browser
5. เมื่อครบเวลา หน้าจะเปลี่ยนเป็นฟอร์มเปิดอัตโนมัติ ลองรหัสผิดหนึ่งครั้งแล้วใช้รหัสที่ถูกต้อง
6. อ่านข้อความและกดเขียนความรู้สึก บันทึก แล้วกลับมาแก้ไขได้
7. กลับหน้าแคปซูลหรือรีเฟรช ต้องกรอกรหัสอีกครั้ง ปุ่มลบต้องพิมพ์ `DELETE` เพื่อยืนยัน
8. ออกจากระบบ แล้วทดลองบัญชีอื่นเพื่อดูว่าไม่เห็นแคปซูลของบัญชีเดิม

วันที่ในหน้าสรุปใช้เขตเวลา Asia/Bangkok ฟอร์มวันเวลาใช้เวลาท้องถิ่นบนอุปกรณ์แล้วแปลงเป็น UTC ก่อนบันทึก

## Server และ Client

- Next.js App Router เป็น React framework ที่รองรับ Server Components และ Server Actions ตาม proposal
- `app/**/page.jsx`: ตรวจ session และอ่านข้อมูลฝั่ง server
- `components/`: ฟอร์ม ตัวกรอง การนับถอยหลัง และ UI ที่มีการโต้ตอบ
- `app/actions.js`: ตรวจผู้ใช้และสิทธิ์ซ้ำทุก mutation พร้อม Zod validation ไม่เชื่อข้อมูลจาก browser
- `lib/auth.js`: บัญชี session และ HttpOnly cookie
- `lib/service.js`: กติกาการสร้าง/เปิดแคปซูล
- `lib/store.js`: เลือกฐานข้อมูล local หรือ Supabase
- `lib/crypto.js`: hash/verify Argon2id พร้อม salt สุ่ม
- `supabase/schema.sql`: ตาราง RLS และ database functions

ค่าฟอร์มใช้ `useState` เพื่อไม่ให้ข้อความหายเมื่อส่งผิด ใช้ `useActionState` แสดงข้อผิดพลาดและสถานะกำลังส่ง ตัวกรองอ่านจาก URL โดยตรง จำนวนแคปซูลคำนวณจากข้อมูล ไม่เก็บ state ซ้ำ ไม่ใช้ Redux/Zustand เพราะยังไม่มี state ส่วนกลางซับซ้อน

## ความปลอดภัยและขอบเขต

- เปิดข้อความได้เมื่อ session เป็นเจ้าของ ถึงเวลา server และรหัสผ่านถูกต้องครบทั้งสามข้อ
- เก็บรหัสผ่านแบบ Argon2id พร้อม random salt ไม่เก็บรหัสผ่านจริง ทั้งบัญชี local และแคปซูล ส่วนบัญชี Supabase ให้ Supabase Auth จัดการ
- ผิดครบ 5 ครั้งในหน้าต่าง 15 นาทีแล้วบล็อกจนหน้าต่างนั้นหมด ตัวนับเก็บในฐานข้อมูล รีเฟรชไม่ล้าง และจองจำนวนครั้งแบบ atomic ก่อน verify เพื่อป้องกันการส่งพร้อมกัน หากสำเร็จจะล้างตัวนับ
- การเข้าสู่ระบบจำกัด 10 ครั้งต่ออีเมลใน 15 นาที (อีเมลใน key ของตัวนับถูก hash)
- ข้อความและ hash แยกจาก metadata รายการ Supabase ปิดสิทธิ์อ่านโดยตรงจาก browser; service-role ใช้เฉพาะฝั่ง server หลังตรวจสิทธิ์
- การสร้างแคปซูลบันทึก metadata/ข้อความ/hash ใน transaction เดียว ลบแคปซูลแล้วลบเนื้อหา รหัสผ่าน และ reflection ด้วย foreign key cascade
- เปิดแล้วไม่ได้เปลี่ยนแคปซูลเป็นสาธารณะ ทุกครั้งที่ขอข้อความต้องกรอกรหัสใหม่ และล้างข้อความจากหน้าจอเมื่อซ่อนแท็บ/ออกจากหน้า
- Server Actions ใช้ POST และ Next.js ตรวจ Origin; session cookie ใช้ HttpOnly, SameSite และ Secure ใน production
- ไม่มี localStorage ไม่มีรหัสใน URL หรือ logs และตอบหน้า private แบบ no-store
- เมื่อปิดผนึกไม่แก้ข้อความหรือวันเปิด กู้รหัสผ่านแคปซูลได้ด้วยรหัสยืนยันทางอีเมลของบัญชี
- Hash ไม่ใช่การเข้ารหัสข้อความ ผู้ดูแลฐานข้อมูลยังอ่านข้อความได้ ระบบนี้ไม่ใช่ end-to-end encryption
- โหมด local ต้องใช้เครื่องเดียวพร้อมดิสก์ถาวร ไม่เหมาะกับ serverless หลาย instance หาก deploy ให้ใช้ Supabase และ HTTPS
- ฟอนต์ Google Fonts โหลดผ่านอินเทอร์เน็ต มี Tahoma/sans-serif fallback และภาพทั้งหมดสร้างในโปรเจกต์เองด้วย CSS/SVG

## อีเมลแจ้งเตือนและลืมรหัสผ่าน (อัปเดต)

ไอคอนประกายและแม่กุญแจเปลี่ยนเป็นไอคอนเส้น Lucide สีชมพูหม่นเหมือนปุ่มลบ

### ตั้งค่าครั้งแรก

1. คัดลอก `.env.example` เป็น `.env.local` ถ้ายังไม่มีไฟล์นี้ อย่าทับค่าที่ตั้งไว้แล้ว
2. สมัคร [Resend](https://resend.com) และยืนยันโดเมนผู้ส่ง จากนั้นกรอก `RESEND_API_KEY` และ `EMAIL_FROM` ฝั่ง server เท่านั้น
3. ตั้ง `APP_URL` ให้ตรง URL ที่ใช้เปิดเว็บ เช่น `http://localhost:5200` ตอนรันในเครื่อง หรือโดเมน HTTPS เมื่อเผยแพร่
4. สร้าง `CRON_SECRET` แบบสุ่มอย่างน้อย 32 ตัวอักษร ด้วยคำสั่งที่ระบุใน `.env.example`
5. หากใช้ Supabase ให้รันส่วน **Email upgrade** ท้าย `supabase/schema.sql` โหมด SQLite สร้างตารางเพิ่มให้อัตโนมัติโดยไม่ลบข้อมูลเดิม
6. รีสตาร์ตเว็บ แล้วเปิด Terminal อีกหน้าต่างในโฟลเดอร์โปรเจกต์ รัน `npm run notifications` เพื่อเช็กทุกหนึ่งนาที

ต้องเปิดทั้ง server และตัวตรวจแจ้งเตือนไว้ แต่ผู้ใช้ปิดเบราว์เซอร์ได้ ถ้าเครื่องหลับ/ปิด ตัวตรวจจะส่งเมื่อกลับมาทำงาน ไม่รับประกันตรงวินาที หากเผยแพร่จริงให้ระบบ scheduler เรียก **POST `/api/cron/notifications`** ทุกนาที พร้อม `Authorization: Bearer <CRON_SECRET>` อย่าส่ง secret ใน URL

### วิธีใช้

- หน้าแคปซูลมี **รับอีเมลเมื่อถึงเวลาเปิด** กดส่งรหัส แล้วใส่รหัส 8 หลักจากอีเมลเพื่อยืนยันการรับแจ้งเตือนสำหรับแคปซูลนั้น
- **ลืมรหัสผ่านแคปซูล**: ต้องเข้าสู่บัญชีเจ้าของก่อน ขอรหัสจากอีเมล แล้วกรอกรหัสและรหัสผ่านแคปซูลใหม่สองครั้ง
- รหัสใช้ได้ครั้งเดียว ภายใน 10 นาที ขอใหม่ทำให้รหัสเดิมของรายการนั้นหมดผล จำกัดการส่ง 3 ครั้งต่อบัญชี/15 นาที และตรวจ 5 ครั้งต่อแคปซูล/15 นาที ขอใหม่ไม่ล้างจำนวนครั้ง
- ตรวจเจ้าของอีกครั้งฝั่ง server และเปลี่ยนรหัสพร้อมใช้รหัสยืนยันใน transaction เดียว จึงไม่สามารถใช้รหัสพร้อมกันซ้ำได้
- ไม่ส่งข้อความส่วนตัวหรือรหัสผ่านแคปซูลทางอีเมล การตั้งรหัสใหม่ไม่เปลี่ยนวันเปิด และยังต้องใส่รหัสใหม่เมื่อถึงเวลา
- ฟีเจอร์นี้กู้ **รหัสแคปซูล** ไม่ใช่รหัสเข้าบัญชี หากเข้าอีเมลไม่ได้จะกู้ด้วยขั้นตอนนี้ไม่ได้
- แจ้งเตือนที่บริการอีเมลรับแล้วจะถูกทำเครื่องหมายส่งแล้ว และใช้ idempotency key ลดการส่งซ้ำ กรณีส่งล้มเหลวจะลองใหม่รอบถัดไป (กรณีฐานข้อมูลล้มหลังส่งสำเร็จนานเกินช่วงเก็บ key ของผู้ให้บริการ ยังอาจส่งซ้ำได้)
